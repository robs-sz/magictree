A stack for every worktree

magictree gives each git worktree its own ports, environment and supervised processes, so several branches run side by side without colliding.

Name a branch, get a stack

A worktree needs no configuration of its own. Type a branch name and see the checkout it gets, the ports it is dealt and the URLs its services answer on. 


            

              
              
              
              
              
              
              
              How ports are dealt
            

          


          

            The repository here is called shop. Blocks are twenty ports each, dealt from 20000 to 32767;
            the block your worktree gets depends on the repository and on what is already taken.
          

        

      


      

        

          
From one checkout to many

          
        


        

          

            

              Once, in the primary checkout, magictree reads the repository (its
              package scripts, Compose files, justfile and lockfiles) and writes what it found into a
              manifest you commit. A worktree inherits only what git tracks, so the manifest is the
              whole setup.
            

            
$ magictree discover && magictree init
$ git add magictree.toml && git commit -m "add magictree.toml"

          


          

            

              Then one command starts the stack. It claims the ports, runs the
              bootstrap steps, starts the containers and the host processes in dependency order, and
              waits for each one to be healthy before the next.
            

            
$ magictree up
[1/3] compose compose.yaml (project main) · db
     db: starting → healthy
[2/3] service · api
     api: started (pid 48190)
     healthy
[3/3] service · web
     web: started (pid 48211)
     healthy

web   http://localhost:5173
api   http://localhost:8000

          


          

            

              For each branch after that, a new worktree appears beside the checkout
              with a stack of its own. The same service binds a different port in every checkout, and
              nothing you start in one can take a port from another.
            

            
$ magictree new feat/billing
$ magictree list
worktree           path                  ports
shop-feat-billing  ../shop-feat-billing  db=24100 api=24101 web=24102
shop-fix-checkout  ../shop-fix-checkout  db=27360 api=27361 web=27362

          


          

            

              When the branch is merged, removing the worktree stops its stack,
              deletes the checkout and gives its ports back. The branch itself is kept, and nothing
              is left behind for a later clean-up.
            

            
$ magictree rm feat/billing

          

        

      


      

        
What every worktree gets

        

          

            

              
Its own block of ports

              

                Twenty ports per worktree, stable across restarts. The primary checkout keeps the
                ports the repository already uses.
              

            

            
$ magictree ports
worktree shop-feat-billing (generated ports, block 24100-24119)
db     24100  http://localhost:24100
api    24101  http://localhost:24101
web    24102  http://localhost:24102

          


          

            

              
A checkout that stays clean

              

                Ports, environment, logs and pid files live in magictree's own state directory. No
                file is written into the repository.
              

            

            
$ git status --short
$ ls ~/.local/state/magictree/worktrees/*/shop-feat-billing
env  log  ports.json  run

          


          

            

              
One manifest for all of them

              

                A service names its command, the variable its port arrives in, what it needs first
                and how to tell it is up.
              

            

            
[[services]]
id = "web"
target = { kind = "pnpm", script = "dev" }
port = { env = "PORT", prefer = 5173 }
needs = ["db"]
health = { http = "/", timeout = 60 }

          


          

            

              
A URL that names the branch

              

                Mark a port as a browser alias and each worktree answers on its own hostname, so
                cookies and tabs from two branches never mix.
              

            

            
port = { env = "PORT", browser_alias = true }

http://shop-feat-billing.localhost:24102
http://shop-fix-checkout.localhost:27362

          


          

            

              
Containers and processes together

              

                Compose services and plain commands are one stack with one dependency order, one
                health check and one place to read their logs.
              

            

            
$ magictree status
db      compose  running (healthy)
redis   compose  running (healthy)
api     host     running (pid 48190)
web     host     running (pid 48211)
worker  host     stopped

          


          

            

              
The same ports in your shell

              

                One line in your rc file keeps the shell's environment in step with the worktree it
                is in, for every tool and agent started from it.
              

            

            
$ eval "$(magictree activate zsh)"
$ cd ../shop-feat-billing
$ echo $PORT
24102

These are the commands.
          

          Command reference
        


        

          

            
            
            
            
            
          


          

            

              
discover
Read the repositoryReports what a stack would need, from Compose files, package scripts, justfiles and lockfiles.
--json

              
init
Write the manifestAsks only what it has not been told before, and never rewrites a service you edited.
--accept-defaults

              
doctor
Detect driftChecks the manifests against what the repository says now.
-C <dir>

            

            

              
up
Start this worktree's stackPorts, bootstrap, services in dependency order, health.
--quiet · --no-build

              
down
Stop itVolumes and ports are kept, so the next start is the same stack.
--volumes

              
restart
Restart the services you nameOn the ports they already have; nothing else is touched.
--build

              
exec
Run a command as the stack wouldWith this worktree's ports and environment on top of your own.
-- just api::seed

            

            

              
magictree
The screenServices, worktrees, ports, environment and logs, with every action a key away.
no command

              
status
What is running, and whereEach service's process or container state and its URL.
--probe

              
logs
A service's outputOne service, or the whole stack with Compose included.
-f · --all

              
ports
This worktree's portsThe assignment as URLs.
--release

              
env
The resolved environmentAs a dotenv file, as exports, or with the layer that set each value.
--explain

            

            

              
new
Create a worktree and start its stackBeside the primary checkout, on a new or existing branch.
--no-up

              
list
Worktrees and their portsFor this repository, or every one magictree has recorded.
--all

              
rm
Remove a worktreeStops it, deletes the checkout, releases its ports. The branch is kept.
--force

              
gc
Reclaim what deleted checkouts leftPort blocks, containers and processes of worktrees that are gone.
--all

            

            

              
activate
Keep a shell in step with its worktreeFor zsh, bash and fish.
--install

              
completion
Shell completionA script for bash, zsh, fish, elvish or powershell.
zsh

              
update
Install the latest releaseOver the running binary, only after the new one has proved it runs.
--check

            

          

        

      


      

        
Install magictree

        

          Install magictree with
          curl -fsSL https://raw.githubusercontent.com/robs-sz/magictree/main/install.sh | sh
          
        

        

          The script downloads the release built for your machine, checks that it runs, and puts one
          binary in ~/.local/bin. Releases exist for macOS on Apple silicon and Intel and for Linux on
          x86-64; the same archives are on the
          releases page. After that,
          magictree update keeps it current.
